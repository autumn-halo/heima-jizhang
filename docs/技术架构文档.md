## 二、总体架构（Electron 三层结构）

```
┌─────────────────────────────────────────────────────────────┐
│ 渲染进程 Renderer（Vue 3 + Element Plus + ECharts）          │
│  · 页面：首页 / 记一笔 / 账户管理 / 统计图表 / 分类管理        │
│  · Pinia 状态管理、vue-router(hash) 路由                     │
│  · api/index.js 统一封装 {ok, data|error} 解包               │
└──────────────────────────┬──────────────────────────────────┘
                           │ contextBridge 白名单（window.api）
┌──────────────────────────▼──────────────────────────────────┐
│ 预加载脚本 Preload                                          │
│  · contextIsolation: true / nodeIntegration: false（安全基线）│
│  · 仅暴露声明式 API，渲染进程无法接触 Node/文件系统            │
└──────────────────────────┬──────────────────────────────────┘
                           │ ipcRenderer.invoke ↔ ipcMain.handle
┌──────────────────────────▼──────────────────────────────────┐
│ 主进程 Main（Node.js 环境）                                  │
│  · 窗口生命周期管理（BrowserWindow）                          │
│  · IPC 层：参数校验 + 统一返回结构（ipc.js）                  │
│  · 数据层：node:sqlite 内置模块（db.js，零原生依赖）           │
│  · 每日自动备份（backup.js，VACUUM INTO + 保留30份）          │
└──────────────────────────┬──────────────────────────────────┘
                           │ SQL
┌──────────────────────────▼──────────────────────────────────┐
│ SQLite 数据库（%APPDATA%\黑马记账\黑马记账.db）               │
│  · expenses（收支流水）/ categories（两级分类）               │
│  · accounts（两级账户）/ settings（键值设置）                 │
└─────────────────────────────────────────────────────────────┘
```

**设计要点**

- **职责分离**：界面只发命令、主进程管数据，中间以白名单 IPC 隔离（最小权限原则）
- **金额精度**：金额一律以「分」为整数存储运算（`amount_cents INTEGER`），杜绝浮点误差
- **数据安全**：数据存系统用户目录（卸载不丢）；每日首次启动自动备份（SQLite `VACUUM INTO` 在线备份），保留最近 30 份；同一天不重复备份
- **版本兼容**：数据库结构迁移（`migrate()` 用 `PRAGMA table_info` 探测缺失字段再 `ALTER TABLE`），老账本无缝升级（v1.0 → v1.3 四次迁移全部兼容）

## 三、核心主链路（以「记一笔」为例）

```
用户输入金额/分类/账户 → 前端校验
  → api.expenses.create()（统一解包层）
  → window.api.expenses.create()（preload 白名单桥）
  → ipcRenderer.invoke('expenses:create', payload)
  → 主进程 validateExpensePayload() 参数校验：
      金额整数分>0、二级分类存在且 kind 匹配收支类型、账户存在、日期合法
  → node:sqlite INSERT INTO expenses
  → 返回 { ok: true, data: { id } }
  → 前端 ElMessage 成功提示 + 表单重置 + 记忆习惯（localStorage）
```

**首页查询链路**：`expenses:list`（type/accountId/月份筛选 + LEFT JOIN 联表带出分类名/账户名）→ 前端按月分组折叠、按日排列渲染。

**统计链路**：`expenses:summary`（SUM/COUNT 聚合 + 一级分类 GROUP BY + 近 6 个月循环查询）→ ECharts 环形图 + 柱状图。

**备份链路**：应用启动 → `settings.last_backup_date` 非今天 → `VACUUM INTO '黑马记账-backup-YYYY-MM-DD.db'` → 清理超出 30 份的旧备份。

## 四、数据库设计

```sql
-- 收支流水：金额存"分"，type: expense|income，account_id 可指向两级账户
CREATE TABLE expenses (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  amount_cents INTEGER NOT NULL,
  category_id INTEGER NOT NULL REFERENCES categories(id),
  expense_date TEXT NOT NULL,          -- YYYY-MM-DD
  note TEXT NOT NULL DEFAULT '',
  type TEXT NOT NULL DEFAULT 'expense',
  account_id INTEGER REFERENCES accounts(id),
  created_at TEXT DEFAULT (datetime('now','localtime'))
);

-- 两级分类：parent_id NULL=一级大类；kind: expense|income
CREATE TABLE categories (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  parent_id INTEGER REFERENCES categories(id) ON DELETE CASCADE,
  sort_order INTEGER NOT NULL DEFAULT 0,
  kind TEXT NOT NULL DEFAULT 'expense'
);

-- 两级账户：parent_id NULL=一级账户（微信/支付宝/银行卡），非NULL=具体卡
CREATE TABLE accounts (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL UNIQUE,
  parent_id INTEGER REFERENCES accounts(id),
  sort_order INTEGER NOT NULL DEFAULT 0
);

-- 键值设置：备份日期等
CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT NOT NULL);
```

关键实践：`PRAGMA journal_mode = WAL`（读写并发更好）、`PRAGMA foreign_keys = ON`（级联删除）、**部分唯一索引**（SQLite 普通唯一索引对 NULL 失效，一级分类重名防护需 `WHERE parent_id IS NULL`）、分类树用「三遍遍历」组装避免行序依赖。

## 五、技术栈清单

| 层 | 技术 | 版本 | 用途 |
|---|---|---|---|
| 桌面框架 | Electron | ^44.7.2（内置 Node 24） | 跨平台桌面容器 |
| 界面框架 | Vue 3（Composition API） | ^3.5 | 响应式 UI |
| 构建工具 | electron-vite | ^6.0 | 主/预加载/渲染三端构建 |
| UI 组件库 | Element Plus | ^2.14 | 表单/表格/弹窗/级联/折叠等 |
| 图表 | ECharts + vue-echarts | ^6.1 / ^8.3 | 环形图、柱状图（按需注册） |
| 状态管理 | Pinia | ^4.1 | 分类/账户全局缓存 |
| 路由 | vue-router（hash 模式） | ^4.6 | 打包后 file:// 加载必须 hash |
| 数据库 | node:sqlite（Node 内置） | Node 24 内置 | SQLite 驱动，零原生编译 |
| 打包 | electron-builder | ^26.15 | Windows NSIS 安装包 |
| 测试 | Playwright（playwright-core） | — | `_electron.launch` 驱动真实应用做端到端测试 |

**技术选型理由**：Electron 生态成熟、界面美观；node:sqlite 内置模块省去原生模块编译（better-sqlite3 的常见坑）；ECharts 中文资料丰富；Element Plus 中文文档完善。

## 六、关键方法与包（代码中实际使用）

**Node 内置 node:sqlite**
- `new DatabaseSync(path)`、`db.exec()`（建表/PRAGMA/VACUUM INTO）
- `db.prepare(sql).run()/.get()/.all()`（参数化查询，防注入）
- `PRAGMA table_info()`（迁移探测）、`VACUUM INTO`（在线备份）

**Electron 主进程/预加载**
- `app.whenReady()`、`BrowserWindow`（窗口/图标）、`app.getPath('userData')`
- `ipcMain.handle()`（主进程处理）、`ipcRenderer.invoke()`（渲染进程调用）
- `contextBridge.exposeInMainWorld('api', api)`（白名单桥）
- `electron-builder`：NSIS 打包、`installerLanguages: zh_CN`

**Vue 3 / Pinia / Router**
- `ref / reactive / computed / watch / onMounted / nextTick`
- `defineStore`（state/getters/actions）、`createRouter` + `createWebHashHistory`

**Element Plus**
- `ElMessage / ElMessageBox.confirm`、`el-cascader`（两级级联）、`el-collapse`（月份折叠）、`el-select` 分组、`el-date-picker`、中文语言包 `zh-cn`

**ECharts 按需注册**
- `use([CanvasRenderer, PieChart, BarChart, TooltipComponent, GridComponent])`
- 色板通过色盲/对比度校验脚本验证（OKLab ΔE 标准）

**Playwright 端到端测试**
- `_electron.launch({ executablePath, args: [appDir] })`
- `page.click / fill / evaluate / waitForSelector / screenshot / reload`
- 关键坑：el-select 下拉必须用 `page.click` 真实事件（DOM `el.click()` 会被 click-outside 逻辑关闭）

**npm 包清单**（dependencies/devDependencies）
- 运行时：@electron-toolkit/preload、@electron-toolkit/utils
- 开发：electron、electron-vite、electron-builder、vue、element-plus、echarts、vue-echarts、pinia、vue-router、@element-plus/icons-vue、playwright-core、cross-env、eslint、prettier

## 七、工程质量实践（面试亮点）

1. **端到端自动化测试**：Playwright 驱动真实 Electron 应用，覆盖增删改查、筛选、拦截、习惯记忆、删除保护等 62+ 断言；测试数据自种自清（node:sqlite 直插 + 脚本末尾清理）
2. **AI 智能体协作开发流程**：需求 → 产品文档（CLAUDE.md）→ 方案列优缺、用户拍板 → 分阶段实现 → 每阶段全量回归 + git 存档 → 打包交付。全程人工零代码，但架构/数据库/安全设计均经专业评审
3. **数据迁移兼容**：4 个版本迭代，老账本文件自动升级不丢数据
4. **国内网络适配**：npm 镜像 + Electron 二进制镜像 + 打包工具镜像（npmmirror）
5. **图标工程化管线**：Canvas 自动取景裁剪 + 赛璐璐风格化 + 手写 ICO 多尺寸编码器（含踩坑：PowerShell 生成的 ico 不合规被 electron-builder 静默跳过）
6. **开发环境坑**：`ELECTRON_RUN_AS_NODE` 环境变量使 Electron 退化为纯 Node → 启动保护器彻底删除该变量
